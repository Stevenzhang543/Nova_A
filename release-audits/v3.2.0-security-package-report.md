# Nova_A 3.2.0 security and package-permission report

Status: applicable local controls passed; no third-party security attestation is claimed.

- No new npm, Cargo, Tauri, or browser dependency was introduced by the schema-23 implementation.
- The SPDX inventory contains 672 unique locked npm/Cargo package identities. Cargo checksums are retained where present; license fields remain `NOASSERTION` pending legal inventory review.
- `pnpm audit` reported no known package vulnerability at capture time.
- Runtime API 1, Plugin API 2, and Package Manifest 1 remain unchanged. Plugin browsing remains metadata-only; installation/enablement remains explicit and permission-gated.
- Generated import artifacts are visibly read-only. Manifest directories reject empty/parent-traversal paths.
- Project/import parsers bound collections and reject future schema mutation, invalid stable identities, non-finite values, hierarchy cycles, unsafe asset paths, invalid component dependencies, and malformed package/plugin data.
- Migration, repair, cache import, asset replacement, and project open are staged/validated before commit and preserve a rollback/last-valid value.
- External source linking is explicit. External-change choices are keep current, reimport, or import as copy.
- Native capabilities retain the limited window operations required for maximize, bounds recovery, and F11. No broader filesystem/network/process permission was added for v3.2.

Pending: independent supply-chain/license review, signed provenance, Authenticode signing, and third-party penetration testing.
