# Nova_A 3.2.0 installer and platform report

## Measured locally

- Tauri release compilation passed on Windows x86-64.
- Portable `nova_a.exe`, WiX MSI, and NSIS setup executable were produced from the same working-tree build.
- The portable executable launched successfully and created a normal decorated, resizable, maximized window.
- The final native runner could not reuse WebView2's transient debugging endpoint for an automated F11 transition; this is recorded as `passed-with-gap`, not a pass. The same global F11 route entered/exited fullscreen in the clean-profile browser qualification, while native `setFullscreen` permissions/wiring passed static audit.
- The deployable Web build passed a fresh-profile Edge 147 editor run at four reference resolutions.
- Web archive generation includes HTTP(S)/WASM hosting instructions, schema-23 metadata, and internal SHA-256 checksums.

## Pending and therefore not claimed

- Install, upgrade, repair, and uninstall on a clean Windows VM.
- Authenticode signature and signed Git-tag provenance.
- Firefox and WebKit Web packages.
- Linux, macOS, and Android native exports.
- Windows discrete-GPU vendor matrix and 125/150/200 percent OS scaling.
- A repeat of the native F11 transition against the final executable in a fresh interactive Windows session.

Tauri printed an absent `__TAURI_BUNDLE_TYPE` updater marker warning while creating MSI/NSIS. Nova_A 3.2 does not include or advertise an updater plugin. Ordinary portable/MSI/NSIS output was created; updater-based delivery remains disabled until separately qualified.
