# Nova_A 5.0.1 — User-Experience Consolidation Specification

**Document ID:** NOVA-A-UX-5.0.1
**Release type:** 0.0.x usability, visual-quality, localization, and regression correction
**Product owner:** Whitelist
**Implementation status:** Approved for implementation
**Compatibility rule:** No project feature, editor capability, animation, import path, runtime behavior, or supported migration may be removed.

## 1. Release objective

Nova_A 5.0.1 must feel understandable to a first-time user while remaining fast for experienced users. The editor must present one obvious primary route for each task, visually separate primary controls from advanced controls, keep the canvas dominant, and retain every existing command through visible controls, menus, shortcuts, or contextual overflow surfaces.

The visual target is a calm, modern desktop editor influenced by high-quality native creative software: layered materials, restrained depth, soft geometry, crisp typography, purposeful motion, clear focus, and strong content hierarchy. The target is not to imitate another product or add decoration without meaning.

## 2. First-user audit findings

### 2.1 What already works

- The launcher clearly separates opening, migration, importing, templates, and recent projects.
- Design, Script, Animation, UI, Debug, and Manage are useful task-oriented workspaces.
- Contextual side tools, persistent status, command search, workspace layouts, and dockable panels are valuable advanced capabilities.
- Dark mode avoids glare, light mode is intentionally muted, and high-contrast mode is separate.
- Rounded variable fonts, keyboard focus, reduced motion, multilingual content, and layout audits already exist.

### 2.2 Problems to correct

- At common laptop widths the workspace row and scene toolbar contain too many equal-weight controls.
- The scene toolbar uses horizontal scrolling as a normal discovery mechanism.
- Layout toggles, navigation, search, command palette, workspaces, simulation, and scene tools visually compete.
- Several glyph-only actions require memorization and do not expose their name until hover.
- The context rail duplicates routes without enough explanation and truncates translated labels.
- The bottom dock can consume too much canvas and its open/closed state is not visually obvious enough.
- Caption text and metadata are frequently 11 px, which is tiring at normal viewing distance.
- Surface colors are close together, so panel ownership and active depth are harder to scan.
- Accent blue is applied to many unrelated elements; selection, creation, success, warning, and focus need distinct roles.
- Some strings leak translation keys or English text in German/Chinese workflows.
- Long German labels and compact Chinese labels need different wrapping behavior without horizontal overflow.
- Existing animations are present but do not consistently explain workspace, panel, menu, or selection changes.

## 3. Information architecture

### 3.1 Application menu

- Keep File, Edit, Project, Debug, View, and Help.
- Keep destructive actions inside menus and application dialogs.
- Menus use clear grouping, descriptive labels, shortcut hints, strong hover/focus states, and a soft entrance animation.

### 3.2 Workspace switcher

- Design, Script, Animation, UI, Debug, and Manage remain the primary navigation.
- Render the switcher as one visually connected segmented surface.
- Active workspace uses a filled tonal state, accent edge, and short position transition.
- Dirty indicators remain visible but must not overpower the workspace label.
- The current project/context remains visible when space permits and must be translated.

### 3.3 Layout and command controls

- Back and Forward remain directly available.
- Hierarchy, Inspector, Bottom panel, Focus Mode, and workspace management move into one labeled Layout menu on the workspace row.
- Quick Open and Command Palette remain available through one clear Search/Commands control and their shortcuts.
- All moved controls remain available from View and keyboard shortcuts; this is reorganization, not removal.

### 3.4 Context rail

- Retain context-sensitive tools for every workspace.
- Use a wider, calmer rail on desktop with readable two-line labels.
- Active tools use a filled tonal card and a left/accent indicator.
- The Create action remains pinned at the bottom and must be translated.
- On narrow windows collapse labels accessibly while preserving tooltips and names.

### 3.5 Scene toolbar

- Group Create, transform tools, authoring tools, shape tools, transform-space/pivot settings, snapping, arrange/guides, and camera frame into distinct visual clusters.
- Keep Select/Move/Rotate/Scale directly accessible with shortcut badges.
- Keep the current creation and authoring tools; place secondary authoring and shape tools in labeled popovers when width is constrained.
- Prevent page-level horizontal scrolling. A compact overflow menu is allowed; hidden commands must remain named and reachable.
- Use localized labels such as Tools, Transform, Draw, Snap, and View instead of unexplained symbol sequences.

### 3.6 Bottom dock

- Keep all existing tabs and tools.
- Closed state is a slim dock strip; open state has a visible raised header and resize affordance.
- Built-in workspace defaults must preserve canvas priority: Design starts closed, UI uses a moderate Assets dock, Animation/Debug use purpose-specific heights.
- Tab labels may wrap or truncate with accessible titles but must never force horizontal page overflow.

### 3.7 Manage workspace

- Retain Project & Safety, Packages, Project Health, Rendering, and Build Settings.
- Use a stable navigation column with readable label and description.
- Reduce unused header height and strengthen selected-section hierarchy.
- Content cards use consistent section headers, spacing, control rows, and maximum reading width.

## 4. Visual system

### 4.1 Typography

- Default body text: 14 px.
- Dense controls: 13 px.
- Captions/metadata: 12 px absolute default floor.
- Section headings: 16 px; page headings: 22 px.
- Code remains JetBrains Mono; UI remains Nunito Sans with Noto Sans SC fallback.
- Do not use synthetic bold, fractional CSS scaling, raster-scaled text, or uncontrolled component font sizes.
- German may wrap; Chinese must remain horizontal; neither may escape a control.

### 4.2 Dark palette

- Use deep blue-black rather than flat near-black.
- Separate canvas, chrome, panels, raised cards, fields, hover, and popovers with perceptible luminance steps.
- Primary accent: comfortable sky blue.
- Secondary accent: restrained violet used only for gradients/highlight depth.
- Creation accent: teal; selection/focus: blue; success: green; warning: amber; danger: coral red.
- Muted text must remain comfortably readable against every supported surface.

### 4.3 Light palette

- Use cool gray-blue backgrounds rather than white.
- Raised content may approach white but full-window backgrounds may not.
- Borders and fields need clear definition without high-contrast mode.
- High-contrast mode must exceed the default contrast without changing layout.

### 4.4 Shape and depth

- Controls use 9–11 px radii; panels 14–16 px; dialogs 20 px.
- Connected/segmented controls share one outer shape and do not look like unrelated buttons.
- Use subtle inner highlights, one restrained shadow scale, and tonal borders.
- Avoid excessive outlines, heavy black shadows, random gradients, and decorative glass over the canvas.

### 4.5 Icons

- Retain existing functionality but normalize icon boxes and stroke weight.
- Glyph-only buttons require accessible names and visible tooltips.
- Shortcuts are supporting information, not the primary label.

## 5. Motion system

- Workspace content transition: 180–240 ms fade plus 4–8 px directional movement.
- Menus/popovers: 140–180 ms scale/fade from their trigger.
- Panels/docks: 220–280 ms spring-like slide with no layout flash.
- Active segmented indicator: 160–220 ms position/color transition.
- Buttons: subtle hover lift/highlight and compressed press; no bouncing.
- Toasts/tasks/validation states use short opacity/position changes.
- Canvas objects and physics rendering must never inherit UI transforms.
- Reduced-motion preference disables nonessential transforms and smooth scrolling while retaining immediate state feedback.

## 6. Localization and accessibility

- English, German, and Simplified Chinese must contain every newly visible label.
- Fix raw `currentContext`, `create`, version, and other fallback-key leaks.
- Localize migration preflight labels and explanations; dynamic schema/version values remain unchanged.
- Every icon-only command has an accessible name and tooltip.
- Accessible names generated from visible labels or tooltips must update immediately when the editor language changes; stale names from the previous language are release-blocking.
- Keyboard focus remains visible in both themes and high-contrast mode.
- Popovers and menus remain keyboard reachable; Escape closes transient surfaces.
- No horizontal writing-mode regression is allowed in Chinese.
- Test 100%, 125%, 150%, 175%, and 200% UI/DPI scales where supported.

## 7. Implementation requirements

- Introduce centralized 5.0.1 color, typography, spacing, radius, elevation, and motion tokens.
- Rebuild WorkspaceBar into primary workspace navigation plus compact Layout and Commands groups.
- Reorganize ToolBar into named clusters with a responsive secondary-tools popover.
- Improve SideBar readability and active-state hierarchy.
- Improve top bar, status bar, bottom dock, Manage navigation, dialogs, fields, and cards through shared tokens.
- Update launcher surfaces and recent/template cards without changing creation/import behavior.
- Update all product authorities and release labels to 5.0.1; schema remains 29 and public 5.x contracts remain frozen.
- Add a 5.0.1 static UI audit and a multilingual browser/layout qualification.
- Update the offline manual/README with the 5.0.1 organization model and control locations.

## 8. Non-regression rules

- Do not remove a feature, animation, command, shortcut, panel, import path, setting, project field, runtime property, or migration path.
- Do not change physics units, calculations, rendering order, collision behavior, asset identity, scripting semantics, or build output behavior.
- Do not introduce editor-wide CSS transforms that blur text or canvas output.
- Do not hide a command without an accessible menu, popover, or shortcut route.
- Do not replace application dialogs with browser alerts/confirms.
- Existing 5.0 projects and workspace document 3 layouts must open without destructive migration.

## 9. Required audit matrix

### 9.1 Static and type checks

- TypeScript/Vue typecheck.
- 5.0.1 UI contract audit: required tokens, navigation groups, translations, accessible labels, motion/reduced-motion hooks, and version authorities.
- Existing manual, editor shell, scripting, rendering, animation, typography, 5.0 contract, and runtime audits.
- Rust formatting, Clippy with warnings denied, and all workspace tests.

### 9.2 Visual and responsive checks

- Launcher, Design, Script, Animation, UI, Debug, and every Manage section.
- English, German, and Chinese.
- Dark, light, and high-contrast modes.
- 1280×720, 1366×768, 1600×900, 1920×1080, and representative 4K/DPI profiles.
- Bottom dock open/closed, hierarchy open/closed, inspector open/closed, focus mode, menus, popovers, dialogs, and command palette.
- Assert no overlap, text clipping, viewport-level horizontal overflow, untranslated visible keys, missing focus names, or off-screen popovers.

### 9.3 Interaction checks

- Create/open/migrate project flows.
- Switch every workspace and Manage section.
- Open every reorganized Layout and Tools command.
- Toggle panels, bottom dock, focus mode, themes, contrast, compact mode, reduce motion, and all languages.
- Select, move, rotate, scale, create shapes, open snapping/arrange/guides, and change camera frame.
- Open Script, UI, Assets, Console, Animation, Audio, Profiler, Rendering, Health, Packages, and Build surfaces.

### 9.4 Build and release checks

- Production Web/WASM build.
- Windows portable, MSI, and NSIS builds plus isolated startup smoke.
- Reference-project Windows/Web CI.
- Exact eleven-file release package under `releases/v5.0.1/`.
- SHA-256 verification, release notes, complete edit ledger, evidence archive, source archive, web package, reference projects, license, MSI, setup, and portable executable.

## 10. Acceptance criteria

- A first-time user can identify where to create content, edit objects, script, animate, author UI, debug, configure the project, and build without searching multiple unrelated rows.
- At 1280×720 the application has no page-level horizontal scrollbar and the canvas remains usable.
- All commands moved into menus remain discoverable by localized labels and accessible names.
- Typography meets the 14/13/12 px role system by default.
- Dark and light themes have clear layer separation; light mode is not a flashbang.
- Every language passes the full layout matrix without overlap, clipping, vertical text, or fallback keys.
- Reduced motion, high contrast, keyboard focus, and UI scaling remain functional.
- All existing feature, physics, renderer, scripting, migration, and build audits pass.
- Release artifacts identify version 5.0.1 while schema 29 and frozen 5.x contracts remain unchanged.

## 11. Release status policy

5.0.1 is a corrective release on the frozen 5.x candidate line. Local build and audit evidence may qualify the package as a local candidate. External certification gates inherited from 5.0.0—wall-clock soak/observation, independent machine/browser/hardware verification, signing, clean-machine lifecycle, exact tagged source, and independent sign-off—must remain explicitly pending until genuinely completed.
