# Nova_A Project Format 2 — schema 23 release specification

The normative implementation companion is `docs/PROJECT_FORMAT_2_SCHEMA_23.md` in the source archive.

## Identity and manifest

Every project declares `projectFormat = "Nova_A Project Format 2"`, major `2`, schema `23`, engine `3.2.0`, project UUID, compatible engine range, package-lock reference, build-preset references, and named source/shared/generated/cache/user-local directories. Project, asset, scene, entity, prefab-instance, scene-instance, and object-local UUIDs are stable persistent identities. Paths describe location; they are not identity.

## Canonical text

Canonical documents are UTF-8 JSON, two-space indented, use LF line endings, and end with exactly one LF. Object keys are lexicographically sorted. Set-like arrays use documented stable keys; scene/entity/component authoring order remains semantic and is preserved. Numbers must be finite, negative zero becomes zero, and insignificant representation differences are normalized. Unknown fields are retained through load/migrate/save.

## Scene, prefab, and resource records

Scene and prefab instances record stable source UUID/local UUID layers plus explicit overrides. Nested layers are permitted; dependency cycles are invalid. Apply, Revert, individual Reset, Compare, and outer-layer Unpack retain or remap identities according to the operation. Asset metadata contains importer identity/version, source/artifact SHA-256, import settings, dependencies, reverse dependencies, preview/cache state, and generated/read-only ownership.

## Migration and compatibility

The ordered registry accepts public schemas 5–23. Migration is copy-on-write: analyze, preview, back up the complete source document, migrate in memory, validate schema/components/references/packages, then replace atomically. Any exception or failed validation retains/restores the prior project. Schema greater than 23 is never mutated and opens only in the read-only compatibility viewer.

## Conformance evidence

Conformance requires byte-identical no-op saves, repeated-save determinism, complete 5–23 migration results, interruption rollback, stable references after asset move/rename and hierarchy duplication, nested override persistence, component dependency validation, and bounded 50,000-asset indexing/search. The corresponding machine-readable reports are included beside this specification in release evidence.
