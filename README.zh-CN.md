# Nova_A 2D 游戏引擎与编辑器

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](./LICENSE.md)
[![Platforms](https://img.shields.io/badge/platform-Windows%20%7C%20macOS%20%7C%20Linux-lightgrey)](https://v2.tauri.app/start/prerequisites/)
[![Release](https://img.shields.io/badge/release-2.4.0-63c6ff)]()

Nova_A 是一款开源 2D 游戏引擎与桌面编辑器，使用 Rust、WebAssembly、Vue 3 与 Tauri 构建。

版本 **2.4.0** 将动画升级为完整制作流程：摄影表、曲线与切线编辑、多轨道和多目标、框选、吸附、复制粘贴、信号事件、动画图层与遮罩、混合树、可中断过渡、二维骨架、加权蒙皮、IK、约束、录制、确定性重导入和通用时间轴。Project Format 2 升级至 Schema 17；未被项目引用的骨架、蒙皮和时间轴资源不会进入 Player 包。

**手册：** [中英德三语交互网页](./manual/index.html) · [中文 Markdown](./manual/MANUAL.zh-CN.md) · [English](./manual/MANUAL.en.md) · [Deutsch](./manual/MANUAL.de.md)

## v2.4.0 更新内容

- 专用“动画工作室”会按资源类型打开剪辑、控制器、动画遮罩、骨架、蒙皮和时间轴，不再把所有功能堆成一个长表单。
- 动画剪辑支持摄影表、采样曲线、Auto／Linear／Constant／Free 切线、框选与多选、吸附、关键帧拖动、复制粘贴、精灵帧、事件信号及跨对象轨道。
- Animator 控制器支持类型化参数默认值、条件、退出时间、过渡时长和中断策略、图层权重、叠加、遮罩、子图、一维混合树与运行时实时预览。
- `Skeleton2D` 与骨架／蒙皮资源支持层级骨骼、姿势覆盖、逆绑定加权变形、IK 链和约束，并同时连接 WebGL2 与 Canvas2D。
- `TimelinePlayer` 以固定模拟步驱动动画、音频、相机、事件、可见性和脚本调用；动画事件进入有界信号系统。
- 显式“录制”模式会把检查器和 Gizmo 变换记录成吸附关键帧。动画导入保留目标 GUID，并按映射确定性重采样源轨道。
- 新 TextInput 默认尺寸从过宽的 360 × 88 调整为均衡的 300 × 96。
- Schema 17 在不改变旧剪辑和控制器视觉结果的前提下迁移 Schema 16，校验骨架／蒙皮／时间轴引用，并保留未知资源字段。

### 保留的 v2.3 渲染基础

- 底部“渲染”工具可编辑环境光、阴影质量、颜色空间、调试视图、后处理、用户后处理材质、安全着色器和实时预览。
- 点光、聚光、方向光和区域光遵守渲染层／遮罩；ShadowCaster2D 支持硬／柔和／超高质量，SpriteRenderer2D 法线贴图会改变光照响应。
- 材质保存经校验的着色器、纹理、有限统一变量、混合、采样、颜色空间和颜色写入状态。无效着色器安全回退，不会中断帧。
- 多 Camera2D 支持优先级／堆叠、归一化视口、剔除遮罩、像素完美定位和命名渲染纹理捕获。
- 颜色调整、暗角、泛光、模糊和自定义材质通道均为可选；世界精灵和 UI 图片均支持九宫格。
- 图片导入支持 sRGB／线性元数据和平台压缩变体，同时保留图集、采样和精灵区域设置。
- 渲染诊断显示通道耗时、Draw Call、三角形、纹理、过度绘制、渲染目标及受支持时的 GPU 时间，并可下载 PNG 帧捕获。
- 场景工具栏进入正常文档流，不再覆盖工作区栏和 Canvas 标签；完整清理覆盖层与切换场景时重置选择，消除随机白色控制点残影。

### 保留的 v2.2 脚本基础

- 脚本现为全宽专用工作区，不再挤在资源导入器的狭小文本框中。
- `use "…"` 项目模块具有缺失/循环依赖诊断；包依赖为只读元数据。
- Entity、Component、Animator 与 AudioSource 句柄统一返回 `valid`、`kind`、`id` 和 `error`。
- 自定义、脚本、物理、UI、动画与场景生命周期信号共享安全事件队列。
- `task_wait` / `on_task` 任务跟随对象和场景生命周期自动取消。
- 开发运行支持断点、继续/单步、调用栈、局部变量和安全监视；非开发发布包会移除调试元数据。
- 模板保持真实世界单位，但编辑相机现在默认每世界单位 40 像素，默认对象清晰可见。
- 底部工具使用更大的默认字体和自适应比例布局。

### 保留的 v2.1 编辑器工作区基础

- 五种一键工作区提供专注布局，不删除任何编辑器面板或功能。
- 层级、检查器和底部抽屉可独立显示或隐藏；专注模式临时隐藏界面，不会清除已保存布局。
- 默认设计工作区折叠底部抽屉；本地布局恢复会校验损坏或过时的数据。
- `Ctrl/Cmd+K` 或 `Ctrl/Cmd+Shift+P` 打开支持键盘操作的命令面板，覆盖工作区、视图、设置、所有底部工具、面板开关与布局重置。
- 检查器搜索和常规／变换／渲染／物理／玩法／界面分类消除长距离滚动查找。
- “添加组件”改为始终可见、可搜索、已分类的选择器，仍调用原来的组件创建与撤销路径。
- “视图”菜单的布局命令与 900 × 600 响应式规则在中文、英文和德文下保持可用。

### 保留的 v2.0 引擎基础

- 启动时显示项目管理器，提供新建、打开、导入、继续和本地最近项目。
- 包含四个自审计模板：空白 2D、平台跳跃、俯视角、物理沙盒；教程所需系统缺失时会明确拒绝加载。
- **Nova_A Project Format 2**（Schema 17）保存明确兼容信息和项目身份，并迁移所有受支持的 Schema 5–16。
- 稳定组件 API 2.0 文档覆盖全部内置组件，并继续分离渲染、碰撞、编辑器与运行时职责。
- Rhai 脚本可在按项目和槽位隔离的存档中保存有限数字、布尔、字符串、数组与 Map。
- WASM Plugin API 1 校验清单／模块，只开放日志／事件，不提供文件系统、网络或进程权限。
- 随附的中／英／德手册解释全部编辑器按钮、组件、物理属性、运行时 API、资源流程、构建选项、迁移步骤和三个完整教程。
- CI 在原有代码／WASM／前端检查之外，加入三种桌面操作系统和手册完整性审计。

### 保留的 v1.9 分发与调试基础

- Nova Player 是独立的纯运行时应用模式，仅包含运行时、物理、渲染、音频、脚本、输入和打包资源，不会加载检查器、层级、资源浏览器、编辑网格、菜单或 Gizmo。
- “构建设置”可配置游戏名称、Windows／Linux／macOS／Web 目标、x86_64 架构、场景顺序、启动场景、开发元数据、输出目录和可选的可执行文件内嵌游戏数据。
- `game.nova-pak` 是版本化索引归档，记录每个条目的路径、偏移、MIME／类型、原始大小、可选 gzip 数据块和 SHA-256 校验。项目 JSON 与导入资源只打包一次，不会散落成数百个内容文件。
- Windows 与 Linux 主机原生构建默认输出 Nova Player 和 `game.nova-pak` 两个文件，也可把数据附加到可执行文件并通过校验页脚读取。macOS 保留 `.app` 结构并把数据放在内部播放器旁。Web 构建输出 `index.html`、生产版 Nova Player 模块和 `game.nova-pak`。
- 控制台支持 Trace、Debug、Info、Warning、Error、Fatal，提供分类／搜索过滤、来源信息、最多 2,000 条记录和脚本资源跳转。
- 性能分析器采样真实帧、物理、渲染、脚本、动画与音频耗时，并显示 FPS、可用时的内存、Draw Call、精灵、刚体、接触与脚本实例；历史图可冻结或清除。
- 物理调试器可叠加碰撞器、接触点、法线、休眠刚体、AABB、关节约束和绳索节点。
- 前端异常与 Rust panic 会把版本化诊断日志写入用户 Nova_A 应用数据目录的 `Logs` 文件夹。CI 会验证 Rust 测试／clippy、TypeScript、WASM、生产前端和 Tauri 后端。
- 游戏 UI 现在会显示并可在场景视图中选择；需要时自动创建 Canvas；不同控件拥有可见的默认尺寸；缺失图片有占位图；检查器可直接导入图片；游戏视图 TextInput 使用原生输入层，支持选择、粘贴、密码、输入法、德语与中文。
- 底部标签会换行显示，不再退化为浏览器原生横向滚动条。资源、控制台、动画、性能、Tilemap、项目设置和构建设置分别管理自己的滚动；动画时间刻度和帧控件保持有界且清晰。
- 项目格式 13 保存构建设置；格式 12 与此前所有受支持格式继续自动迁移。

## 引擎工作区

```text
Vue 编辑器
  └─ nova_wasm        唯一 WebAssembly 边界
       ├─ nova_runtime  固定时间、事件、诊断、运行时骨架
       │    └─ nova_physics  刚体、碰撞、求解器、绳、持久化世界
       │         └─ nova_math  向量、变换、AABB、射线、矩形
       ├─ nova_script   沙箱化 Rhai 游戏脚本执行
       └─ nova_format   版本化格式、验证与迁移
```

物理、数学、运行时、脚本和格式 crate 不导入 Vue、DOM、JavaScript 或 Tauri。内部 crate 采用静态链接，因此桌面发布仍是一个完整应用，不需要 Nova_A DLL 插件。

## 支持的构建目标

- 浏览器预览：支持 WebAssembly 的当前 Chromium、Firefox 和 Safari。
- 桌面端：Tauri 2 及其系统 WebView 支持的 Windows、macOS 与 Linux。
- 建议在目标操作系统上构建对应安装包：Windows 生成 NSIS/MSI，macOS 生成 app/DMG，Linux 生成当前 Tauri 工具链支持的包格式。

Nova_A 当前是桌面/网页编辑器；仓库尚未配置 Android 与 iOS 应用目标。

## 通用环境要求

- Node.js 18 或更高版本（`.node-version` 记录了测试版本）。
- pnpm 9 或更高版本（`package.json` 固定了项目使用的包管理器版本）。
- 稳定版 Rust 与 Cargo。
- Rust 的 `wasm32-unknown-unknown` 目标。
- `wasm-pack` 0.14.0 或更高版本。
- Git 以及当前系统需要的原生开发依赖。

安装通用工具与项目依赖：

```sh
corepack enable
corepack prepare pnpm@10.30.0 --activate
rustup target add wasm32-unknown-unknown
cargo install wasm-pack --version 0.14.0 --locked
pnpm install --frozen-lockfile
```

如已安装 `wasm-pack` 0.14.0 或更高版本，可跳过对应命令。Rust 官方的 [`wasm32-unknown-unknown` 说明](https://doc.rust-lang.org/stable/rustc/platform-support/wasm32-unknown-unknown.html)包含目标安装方法。

### 操作系统依赖

请以最新的 [Tauri 官方环境要求](https://v2.tauri.app/start/prerequisites/)为准。

- Windows：安装 Microsoft C++ Build Tools，并选择“使用 C++ 的桌面开发”。Tauri 使用 WebView2；当前 Windows 10/11 通常已自带。生成 MSI 时可能还需要启用 Windows 的 VBSCRIPT 可选功能。
- macOS 10.15 或更高版本：安装 Xcode；仅开发桌面应用时也可安装 Xcode Command Line Tools，并完成首次初始化。
- Debian/Ubuntu Linux：

```sh
sudo apt update
sudo apt install libwebkit2gtk-4.1-dev build-essential curl wget file libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev
```

Arch、Fedora、openSUSE、Alpine、NixOS 等系统请直接使用 Tauri 官方页面中的对应包名，不要套用 Debian 包名。

## 构建与运行

以下命令均在仓库根目录执行。

### 浏览器开发模式

```sh
pnpm dev
```

该命令会先重新构建开发版 WASM，再启动 Vite，避免浏览器加载过期的 Rust 模块。默认地址通常为 `http://localhost:1420`。

### 原生桌面开发模式

```sh
pnpm tauri dev
```

### 完整验证

```sh
pnpm test:core
cargo clippy --workspace --all-targets -- -D warnings
pnpm check
pnpm audit:manual
pnpm build
```

这些命令依次运行全部 workspace 测试（包括完整物理测试套件）、将警告视为错误的代码检查、Vue/TypeScript 类型检查、Release WASM 和优化后的 Vite 前端构建。

### 浏览器生产预览

```sh
pnpm build
pnpm preview
```

### 原生发布包

```sh
pnpm tauri build
```

Tauri 打包前会自动执行 `pnpm build`。不同系统的结果通常位于 `src-tauri/target/release/bundle/` 下。

### 使用 Nova Player 导出游戏

1. 打开 **项目 → 构建设置**。
2. 输入游戏名称；桌面目标请选择与当前主机系统相同的平台，也可选择 **Web**。
3. 排列参与构建的场景，并指定启动场景。
4. 输出目录留空时使用 `Documents/Nova_A Builds/<游戏名>`；也可以输入明确目录。
5. 点击 **构建** 或 **构建并运行**；“构建并运行”用于桌面目标。

默认桌面开发导出有意保持为两个干净文件：

```text
MyGame/
├─ MyGame.exe       # Linux 为 MyGame；macOS 为 MyGame.app
└─ game.nova-pak
```

Windows 与 Linux 可勾选“将游戏数据打包进可执行文件”，生成单个播放器可执行文件。macOS 会把包保留在应用包内部，以免破坏 `.app` 结构和签名。桌面目标采用主机原生构建：Windows 目标在 Windows 构建、Linux 目标在 Linux 构建、macOS 目标在 macOS 构建。Web 导出会生成可部署的 `index.html`、Nova Player 模块／样式和 `game.nova-pak`；请通过 HTTP 提供该目录，不要用 `file://` 直接打开。

## 物理属性绑定情况

配置变化会通过 Vue → `nova_wasm` 以明确的持久化世界命令传入。固定物理步保留在 Rust 内；复用的 Float64 状态缓冲区把运行时变换和绳状态返回渲染器，不进行隐藏单位换算，也不会为每个刚体创建 JavaScript 返回对象。一个配置世界单位严格等于一米；相机缩放只负责将世界坐标转换为像素。

## 项目兼容性

- 新存档使用 **Nova_A Project Format 2**、Schema 17 与引擎版本 `2.4.0`。
- 持久化场景、对象、组件和连接使用 UUID；运行时句柄绝不会写入磁盘。
- 格式迁移与验证集中在 `nova_format`，不会散落在各个编辑器组件中。
- v1.9 格式 13、v1.8 格式 12、v1.7 格式 11、v1.6 格式 10、v1.5 格式 9、v1.4 格式 8、v1.3 格式 7、v1.2 格式 6、v1.1.2 格式 5、更早的对象根节点和旧顶层实体数组仍能加载；只有用户再次保存时才会写成 Format 2。

| 属性 | 求解器/渲染行为 |
| --- | --- |
| 位置、旋转、尺寸 | 直接用于世界变换、碰撞几何、锚点和渲染。 |
| 线速度、角速度 | 每个子步积分并回传渲染器。 |
| 加速度 | 直接加入动态刚体的线加速度。 |
| 密度与质量 | 密度 × 精确形状面积得到质量；编辑质量会同步更新密度。 |
| 自动/手动转动惯量 | 默认使用精确椭圆或凸多边形公式；关闭自动计算后严格使用手动值。 |
| 全局/局部重力与重力倍率 | 每个动态刚体子步都会组合并应用。 |
| 力与扭矩 | 遵循 `F = ma` 与 `τ = Iα`；偏心冲量也会产生角冲量。 |
| 线性/角/空气阻尼 | 每个稳定子步执行指数衰减。 |
| 静态/运动学刚体 | 静态刚体保持固定；运动学刚体只积分配置速度，不受动态力影响。 |
| 恢复系数与阈值 | 只有闭合速度超过阈值时才产生反弹。 |
| 静摩擦/动摩擦 | 顺序冲量先尝试静摩擦，再限制为动摩擦。 |
| 传感器 | 刚体之间会报告重叠诊断但不施加碰撞冲量；物理绳会穿过仅传感器对象。 |
| 渲染排序层/顺序 | 只控制绘制顺序，绝不会改变碰撞行为。 |
| 物理层/掩码/矩阵 | 仅当双方碰撞掩码与项目碰撞矩阵都允许该层组合时才求解接触；零掩码会明确禁用全部接触。 |
| 碰撞器偏移/旋转/形状 | 碰撞几何与渲染几何独立，使用自己的局部变换、材质、传感器状态和形状。 |
| 离散／连续碰撞、休眠、锁定旋转 | 默认 Discrete 刚体使用固定步进；可按对象启用 Continuous 自适应防穿透子步。静止刚体无需接触即可休眠，并会在受力、冲量、碰撞、关节牵引或编辑变换时唤醒；锁定刚体拒绝扭矩和角冲量。 |
| 绳路径与锚点 | 直线和归一化手绘路径会在编辑变换后重新拼接；中心/表面/顶点/边上点锚点跟随当前几何。旧版自动曲线记录仍可读取。 |
| 绳的伸长、弯曲、刚度、阻尼 | 作用于两端约束或每个物理绳分段；每段常数按节点数缩放，因此改变采样数不会改变整条绳的配置刚度或阻尼。 |
| 绳半径、线密度、碰撞 | 半径控制连续线段碰撞和渲染直径；线密度控制精确总质量；排除源对象，并向同图层第三方对象传递大小相等、方向相反的冲量与摩擦。 |
| 绳断裂承重 | 配置的等效质量会使用标准重力与实际伸长/弯曲力比较；过载线段断开后，两段残绳继续模拟。 |
| 绑定 / FixedJoint2D | 使用合并质量和平行轴转动惯量生成同一个组合体运动状态；移除内部重叠边线与接触，外部冲量会带动整个组合体。 |
| TileMap 与 TileSet | 图集区域按格子坐标解析；可见块提交渲染批次，连续静态碰撞格被合并，并在编辑后只重建受影响块。 |
| 物理查询 | 射线、重叠与形状投射使用实际椭圆／凸多边形窄相检测、图层掩码和稳定场景 UUID；TileMap 内部合并碰撞体会去重为所属对象。 |
| 2D 关节 | Fixed、Distance、Revolute、Prismatic 和 Spring 约束在每个物理子步求解；锚点、轴、限位、刚度、阻尼和连接对象碰撞开关均传入 Rust。 |
| 粒子发射器 | 发射、寿命、运动与颜色曲线在固定运行时步长更新；图像粒子进入精灵批次，无纹理粒子使用椭圆绘制，且从不创建物理碰撞体。 |
| 颜色、纹理、透明度 | 仅影响渲染，不改变质量或碰撞几何。 |

## 数值范围

Nova_A 在前端、WASM 和后端完整路径中使用 64 位浮点数。非有限输入会被规范化。一般物理量限制为 ±`1e50`；正的几何尺寸、质量与密度下限为 `1e-6`。

多边形碰撞几何必须保持凸形。求解器至少使用 8 个自适应子步，高速运动时最多 128 个，并在每个子步进行 20 次顺序冲量迭代。这些措施可减少穿透和不稳定，但 Nova_A 仍是离散实时求解器，不是符号或无限精度物理系统。
