copied Nova webpage and the extracted, already-built Nova_A 26.35 Web release.

on your production host. The release is already compiled to static files.

when a project explicitly enables them.

1) Identify the actual Nova document root in your hosting panel. Make a backup
   of the currently deployed Nova folder before changing the live site.
2) Prepare the new folder in staging. Use your host's file manager, SFTP or
   existing deployment process to upload index.html, style.css, app.js and the
   entire online/ tree. Preserve license and third-party attribution files.
3) Confirm online/index.html is directly inside online/, not inside an extra
   dist/ or Nova_A-v26.35-web/ folder. Upload all nested files, not just HTML.
4) Apply only the static-host settings in section 6 that your host needs.
5) Test staging with the checklist in section 8.
6) Publish the completed folder together using your host's staging/promote or
   atomic directory-switch facility. Avoid a partially uploaded live release.
7) Revalidate the landing HTML and bootstrap/manifest files in any CDN cache.
   Open the public URL in a fresh browser tab and repeat the click test.

DEPLOYMENT.txt and deployment/ contain local documentation and QA tools. They
can be kept privately; they are not required for visitors. Uploading them is

6. STATIC-HOST SETTINGS

Use HTTPS for the public site. Local loopback HTTP is sufficient for preview.
Keep landing page and editor assets on the same origin for this arrangement.

Your server must:

  - Use index.html as the directory index.
  - Canonicalize directory URLs with a trailing slash, including /nova/ and
    /nova/online/ (or /online/ when Nova is the document root).
  - Return real 404 statuses for missing JS, WASM, JSON and other files.
    Do not route missing engine assets to the landing HTML or a SPA fallback.
  - Serve .wasm as application/wasm.
  - Serve .js as text/javascript or application/javascript.
  - Serve .css as text/css, .json as application/json, .html as text/html.
  - Serve .webmanifest as application/manifest+json and .woff2 as font/woff2.

Cross-origin isolation (COOP/COEP) is not required by this release. If your site
already uses a Content Security Policy, ensure it permits the release's module
scripts, WebAssembly and same-origin workers. Inspect actual browser errors
before adapting an existing policy; no global policy is supplied or changed.

Caching:

  Revalidate index/player HTML, browser-capabilities.js, manifest.webmanifest,
  player-manifest.json and release-metadata.json (Cache-Control: no-cache).
  Revalidate landing index.html as well. Hashed files in online/assets/ can use
  long-lived immutable caching. Preserve previous hashed assets for open tabs
  during upgrades. No-cache still allows storage; it requests revalidation.

Apache example (optional; only when your host permits these .htaccess
directives). Merge into the Nova directory's existing configuration, rather
than replacing unrelated rules:

  DirectoryIndex index.html
  DirectorySlash On
  AddType application/wasm .wasm
  AddType text/javascript .js .mjs
  AddType application/manifest+json .webmanifest

  <IfModule mod_headers.c>
    <FilesMatch "\.(html|webmanifest|json)$">
      Header set Cache-Control "no-cache"
    </FilesMatch>
    <FilesMatch "^(browser-capabilities\.js|style\.css|app\.js)$">
      Header set Cache-Control "no-cache"
    </FilesMatch>
  </IfModule>

Existing catch-all rewrites must exclude the Nova static directory. Some shared
hosts restrict overrides; a 500 error after an override change means you should
restore that change and configure these settings through the host's panel.

Nginx example for Layout A (server block already has root pointing at the
parent website document root and its normal mime.types loaded):

  location = /nova {
    return 308 /nova/$is_args$args;
  }
  location /nova/ {
    index index.html;
    try_files $uri $uri/ =404;
    add_header Cache-Control "no-cache";
  }

This deliberately uses conservative revalidation for the entire Nova tree;
hashed-asset caching is an optional later optimization. Add a wasm mapping to
your existing MIME configuration if it lacks application/wasm. An existing
regex location or error_page rewrite can override this example; merge it with
the actual host configuration and validate there. This snippet is not a full
TLS/domain server configuration. For Layout B, adapt the scope to / in the
dedicated Nova virtual host. No example configuration was installed or tested
on a production Apache/Nginx server.

Official directive references consulted for these optional examples:
  https://httpd.apache.org/docs/2.4/mod/mod_dir.html#directoryindex
  https://httpd.apache.org/docs/2.4/mod/mod_dir.html#directoryslash
  https://httpd.apache.org/docs/2.4/mod/mod_mime.html#addtype
  https://httpd.apache.org/docs/2.4/mod/mod_headers.html#header
  https://nginx.org/en/docs/http/ngx_http_core_module.html#try_files

7. FIRST USE AND PROJECT FILES

Click Try online mode, then New Project or Open Project. For a new project,
enter a name, choose a starter template and click Create Project. A first-run
guide may appear; follow it or choose Skip for now. The launcher also offers
the bundled manual and English/German/Chinese language selection.

Use File > Save Project to keep a project backup. Depending on browser support,
file access may use a picker or a download. Keep downloaded project files in a
known local folder; browser recovery/storage is not a substitute for backups.
Save before closing a tab, clearing browser data, or updating the deployed
editor. The online deployment adds no shared project-storage service.

The editor is online-only. No service worker provides an offline application
shell, and offline reload is unsupported. An already-loaded tab may keep some
work running in memory, but lazy tools, imports, builds and reload may need the
network. Use landscape on touch devices; portrait shows an orientation prompt.
Physical phone/tablet compatibility and installation were not tested here.

To publish a game, use the editor's Web build and Download Web ZIP action.
Extract that generated game package into a SEPARATE game directory and serve it
over HTTP(S). Keep the exported player, game.nova-pak and integrity metadata
together. Do not overwrite online/ with a game export. This manual concerns
hosting the editor, not configuring a multiplayer game server.

  [ ] online/player-manifest.json returns JSON, not a website HTML page.

  [ ] Inspect the intended browsers and target devices on the public host.

9. UPDATES AND ROLLBACK

For a later engine version, stage a complete new release in a separate directory,
verify its own SHA256SUMS.txt, test it, and update the copied landing version
description. Publish HTML/manifests/assets as one coherent build. Keep an old
deployable copy for rollback. Retain the old hashed assets in the served assets
directory while old tabs may need them; switching to a new directory alone does
not keep those old asset URLs alive. Alternatively use versioned editor URLs
and keep the old version reachable until users have saved and reloaded.

Do not replace just one JS/WASM file or mix a new player manifest with old
assets. Users should save first, then reload to adopt a new deployment. If an
upgrade fails, restore the previous complete website/editor deployment and
invalidate stale HTML/manifest caches. Rollback is a server deployment action;
it does not restore unsaved browser edits.

10. TROUBLESHOOTING

Unstyled landing page:
  Confirm style.css and app.js are beside index.html. Their links must stay
  relative. Inspect their requests for 404 responses or HTML fallback bodies.

Button gives 404:
  Confirm online/index.html exists at the button's resolved URL. Remove any
  accidental extra nesting. Check directory indexes and trailing-slash redirects.

Blank editor / failed module / unexpected token '<':
  A missing JS file may be receiving HTML. Check the requested asset, MIME,
  rewrite rules, letter case, upload completeness and any mixed-build cache.

WASM MIME or initialization error:
  Verify the .wasm response is successful, has application/wasm, and matches the
  release checksum. Then inspect the actual browser error for capability/CSP
  restrictions. Do not edit the compiled WASM file to work around hosting.

Game export cannot find player assets:
  Verify online/player-manifest.json and the full online/assets/ tree. Blocking
  hidden .vite/ metadata is acceptable; the public manifest must remain reachable.

Old page/engine after upload:
  Revalidate HTML and manifests in the CDN/browser, save your project and reload.
  Ensure the entire release is from one version.

Offline reload fails:
  This is the release's declared online-only behavior. Reconnect and use a saved
  project backup; this deployment does not add offline caching.
