# Contributing to Nova_A

Small fixes, reproducible bug reports, documentation improvements and platform
testing are welcome. For a substantial feature or behavior change, describe the
problem and proposed scope in an issue or discussion before implementing it.

## Set up a checkout

Fork [Stevenzhang543/Nova_A](https://github.com/Stevenzhang543/Nova_A), then clone
your fork and create a branch:

```sh
git clone https://github.com/YOUR_USERNAME/Nova_A.git
cd Nova_A
git remote add upstream https://github.com/Stevenzhang543/Nova_A.git
git switch -c fix/short-description
```

Use the repository's development toolchain:

| Tool | Version source |
| --- | --- |
| Node.js 22.22.2 | `.node-version` and `package.json` |
| pnpm 10.30.0 | `package.json` → `packageManager` |
| Rust 1.92.0, clippy, rustfmt, WASM target | `rust-toolchain.toml` |
| wasm-pack 0.14.0 | README installation command and validation CI |

Install Node.js, rustup and your host's native build prerequisites first. See the
[README](README.md#common-prerequisites), [中文说明](README.zh-CN.md#通用环境要求)
and [platform recipes](docs/PLATFORM_26_29.md). Run the following from the
repository root:

```sh
corepack enable
corepack prepare pnpm@10.30.0 --activate
rustup show active-toolchain
cargo install wasm-pack --version 0.14.0 --locked
pnpm install --frozen-lockfile
pnpm build:wasm:dev
pnpm check
```

The rustup command installs the toolchain and components in the checked-in
toolchain file when they are missing. Skip the wasm-pack installation if that
version is already available. Verify with `node --version`, `pnpm --version`,
`rustc --version` and `wasm-pack --version`.

`nova_core/pkg/` is generated by wasm-pack. A fresh clone cannot pass the frontend
type check until these JavaScript bindings and TypeScript declarations exist.
Rebuild WASM after changing Rust exports; do not hand-edit or commit the generated
package. `pnpm dev` rebuilds development WASM and starts Vite on port 1420;
`pnpm tauri dev` starts the native editor using the same frontend.

| Area | Starting point |
| --- | --- |
| Editor entry, panels and layout | `src/App.vue`, `src/components/`, `src/layout/` |
| Editor state, history and project operations | `src/store/`, `src/editor/`, `src/projects/` |
| Gameplay, networking, assets and platform services | `src/runtime/` |
| Canvas/WebGL rendering | `src/renderer/`, `src/components/WorldCanvas.vue` |
| Visual scripting and code synchronization | `src/visual/` |
| Rust math, physics and fixed-step runtime | `crates/nova_math/`, `crates/nova_physics/`, `crates/nova_runtime/` |
| Rhai execution and project schema/migrations | `crates/nova_script/`, `crates/nova_format/` |

Versioned documents and scripts also contain historical release material. Check
the current package version and linked implementation tracker before assuming an
old audit describes the current source.

## Validate your change

Run checks relevant to the code you changed and include their results in the PR.
For a complete local development baseline:

```sh
cargo test --locked --workspace --all-targets
cargo clippy --locked --workspace --all-targets -- -D warnings
pnpm build:wasm:dev
pnpm check
pnpm audit:manual
pnpm test:native-headless
pnpm build
cargo check --locked --manifest-path src-tauri/Cargo.toml
```

The last command requires the desktop prerequisites for your host. For a focused
Rust change, start with `cargo test --locked -p CRATE_NAME`; for an editor change,
exercise the affected UI and its save/reopen behavior as well as checking types.
Add a regression test when fixing a behavior bug, and check the English, German
and Chinese UI when changing visible text or layout.

`pnpm test:native-headless` builds and launches the real native physics command on the
current host. It covers replay, request ordering, rejected input, queries,
reset/shutdown, EOF, input bounds and version identity. Cargo identifies the
executable, so a custom `CARGO_TARGET_DIR` and native executable suffix work.
Normal Cargo network settings apply; set `CARGO_NET_OFFLINE=true` only after
dependencies are cached. These process tests do not certify GUI behavior or
cross-platform bitwise determinism.

Pull requests run `ci.yml` and `nova-validation.yml`. The release matrix runs on
manual dispatch or version tags. Release qualification is a separate workflow;
in particular, `pnpm audit`
consumes versioned release evidence, and the 26.30 native release gate also runs
a Windows window/process probe. Do not manufacture missing reports, change their
version labels or mark another platform qualified to make a local check pass.

## Submit a pull request

Keep a PR focused on one problem. Describe the reproduction, resulting behavior,
tests run and any remaining platform limits. Include screenshots for visible UI
changes and a minimal example project for engine behavior changes when useful.
Do not include build outputs, local caches or unrelated formatting changes. Keep
lockfiles unless the change intentionally updates dependencies.

Before committing, check that `git config user.email` is an email associated with
your GitHub account (a GitHub-provided noreply address is also suitable). Then:

```sh
git diff --check
git add PATHS_YOU_CHANGED
git commit -m "fix: describe the concrete change"
git push -u origin fix/short-description
```

Open a PR from that branch to `Stevenzhang543/Nova_A:main`. You can contribute
through a fork without write access to the upstream repository. Maintainers
review and decide whether to merge; direct collaborator access requires an
invitation from the repository owner.
