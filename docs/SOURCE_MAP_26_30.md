## Working code and supporting files

`src/main.ts` → `App.vue` → ProjectManager/EditorLayout is the editor. `src/player.ts` and `PlayerApp.vue` are the player entries. `src/store/physics.ts` owns authoring snapshots/history and scene state; `src/runtime/GameplayRuntime.ts` orchestrates lifecycle, input, scripts, animation, physics and commands. `src/world/World.ts` sends retained-world data through `nova_wasm`. Rust core lives under `crates/`; Tauri commands, filesystem and desktop hosting live under `src-tauri/`.

There is no conventional HTTP application backend. Much of gameplay and rendering runs in TypeScript in both editor preview and player; Rust is not the sole game runtime. The crate graph is `nova_wasm` → `nova_runtime`/`nova_script`/`nova_format`, with runtime → physics → math.

`node_modules/`, `target/`, `src-tauri/target/`, `dist/`, `nova_core/pkg/` and `release-audits/` are generated dependencies/build/evidence. They are not the files to edit to fix the engine. `reference-projects/` and `tests/` contain authored examples and fixtures; `scripts/` contains build, verification and historical release wrappers. Historical Markdown reports are documentation, not active engine implementations. No files are removed merely because they look like base files.
