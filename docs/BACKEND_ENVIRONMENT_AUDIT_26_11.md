# Nova_A 26.11 backend and environment audit

Audit date: 2026-09-05. This is development evidence against the 26.10 checkout, not a declaration that 26.11 has passed all release qualification. The project format remains major 2/schema 29, the public Rhai API remains 2, and the stable version authority remains 26.10.0 until release qualification.

## Scope and evidence standard

The Rust file inventory covers every first-party `.rs` file under `crates`, `nova_core/src`, and `src-tauri`: 22 source/example/build files. All workspace crate manifests, both Cargo lockfiles at dependency/metadata level, Rust/Node pins, package dependency/script configuration, pnpm workspace policy, Vite/TypeScript configuration, Tauri config/capability/Windows manifest entry points, four CI workflows, and the Git hook were inspected. README.md was used for the claimed architecture and support contract.

Review depth differs: the native command boundary, WASM boundary, runtime timing/event layer, query/body bridge, scripting execution/property/serialization boundary, and migration entry/identity validation received direct implementation review. The larger rope/constraint solver, remaining format settings validators, remaining script command registrations, and historical examples received structure/API/test review, with targeted implementation reads. This is not a claim that every line has an independent proof or that every possible input has been exercised. Every first-party Rust target was compiled and checked with warnings denied; existing tests plus the regressions below were executed.

Historical release reports were not regenerated. Examples bearing historical versions are evidence/benchmark tools, not the editor's entry points. Dependency source was inspected only when needed to establish the actual Rhai `call_fn` behavior; vendored dependencies were not represented as first-party audited code.

The native desktop shell is not a separate physics server. TypeScript communicates with the Rust engine through WebAssembly inside the WebView; Tauri provides native filesystem/export/network/process operations. A renderer-disabled authority player still depends on that player architecture and is not certified here as a no-window server.

## Fixed defects and consequences checked before changes

| Finding | Previous user-visible consequence | 26.11 development change | Regression/evidence |
| --- | --- | --- | --- |
| Rhai global initialization executed twice | A top-level `score_add(1.0)` emitted two commands for one callback. Re-evaluated global declarations shadowed exported properties, so callback changes could be discarded when Rhai rewound the scope. | Call every lifecycle function with `CallFnOptions::eval_ast(false)` after the explicit initialization pass. Global statements execute once per invocation; exported state flows back to the host. | New behavioral test failed with two `ScoreAdd` commands before the change; passes with one command and exported counter progression 0→1→2 through direct and cached execution. |
| Rust event field names did not match TypeScript | `EngineEvent` renamed variants but not fields. The host expected `firstCollider`, `relativeVelocity`, `normalImpulse`, etc., while Rust emitted snake_case. Collision callbacks could receive zero fallback velocity, and telemetry lost values/child identity. | Add `rename_all_fields = "camelCase"` to the live event serialization boundary. | WASM bridge test failed with `firstCollider = null` before the fix; now checks collider IDs, velocity, impulses, forces and joint kind. The enum is Serialize-only; no persisted Rust event deserializer was changed. |
| Query geometry omitted retained collider children | Simulation could collide with a compound child that a ray/overlap/character sweep could not see. Child layers and exact separated geometry were lost at the query boundary. | Build query proxies from each primary and retained child collider. Keep the nearest ray per owner and one overlap result per owner. | New child-offset/layer/gap/ray/overlap/sweep regression failed before the fix. Character regression checks an offset solid child blocks movement and a sensor child does not. All existing query cases still pass. |
| Sensors blocked character movement | Character sweep treated sensor geometry as a blocking surface. | Skip sensor proxies only for character movement's self-excluding sweeps. Public geometric queries still detect sensors. | Solid-to-sensor child edit changes movement from stopping at x≈2 to reaching x=10 while point overlap still detects the sensor. |
| Migration version integers could wrap | `4294967297` cast to `u32` became 1 before future-format checks; malformed values could silently take the legacy path. | Checked conversion for explicit `formatVersion` and `projectFormatMajor`; absent fields retain legacy support. | New regression rejects oversized, negative, fractional, string and null versions; legacy input without the fields still migrates. All 41 format tests pass. |
| Native path validation depended on the host OS | Windows traversal/drive syntax could be ordinary filenames on Unix; empty paths, alternate data streams, device aliases and trailing dots/spaces were not portable. | Normalize separators and validate portable file segments before joining output/project paths. | Expanded native regression includes traversal, UNC, drive, ADS, reserved names, Unicode filenames and legitimate backslash normalization. This is lexical validation, not a claim of symlink-race immunity. |
| CI Node setup contradicted the tested version file | All six setup-node sites used Node 20 while `.node-version` named 22.22.2. | All four workflows now use `node-version-file: .node-version`. | Inspected every setup-node occurrence. CI jobs themselves require GitHub runners and were not executed here. |
| Native strict lint was omitted from root checks | Two existing conditional string chains failed native `clippy -D warnings`. | Equivalent explicit if/else branches for network instance log and Inspector IDs. | Separate Tauri all-target clippy passes; no runtime behavior changed. |
| Build configuration had no working TypeScript gate | The app-only Vue check missed an ES5 default library, absent Node declarations and a widened Vite plugin `apply` type. | Give the config compiler an ES2020 target/library and Node types; remove an obsolete error suppression and an unnecessary asynchronous config wrapper. The main audit adds pinned Node declarations and the config check script. | `tsc --project tsconfig.node.json --noEmit` now passes. Async manual-file copying remains in the plugin's `writeBundle` hook. |
| Reload left the same editor locked out for two hours | The project lease remained in localStorage while its ownership token existed only in document memory. A normal reload destroyed the token without releasing the lease, so reopening the same project offered only read-only access. | Track the owned project and release only its matching stored token on non-BFCache `pagehide`. Preserve cached-document ownership, unrelated/replacement leases and current ownership when a switch is blocked. | The new production-module lifecycle regression failed before the fix and now passes all 13 checks with separate document event targets and shared storage. Actual browser reload is recorded by the main UI audit. |

The Rhai change intentionally corrects duplicated initialization and state loss; projects accidentally relying on the duplicated side effect will behave differently. Event field naming corrects the contract expected by the current frontend. No project schema migration or feature removal is involved. The query change performs additional work proportional to the actual authored child colliders; large-world query caching remains a performance follow-up, not an unmeasured speed claim.

## Backend feature inventory and binding obligations

- Physics: dynamic/static/kinematic bodies; polygon/box, ellipse, sampled capsule and finite segment shapes; compound children and prepared Chain/Concave pieces; offsets, rotations, layers and masks; sensors and one-way surfaces; gravity, damping, force/impulse/torque; mass/inertia, rotation lock, sleeping, adaptive CCD; contacts, friction/restitution and combine modes; joints/motors/limits/breakage; segmented rope physics and owner/third-party collision behavior; ray/overlap/sweep/character queries; retained buffers, checksums and diagnostics. Primary body ABI is 56 f64 scalars; child ABI is 21 scalars, maximum 128 children; connection ABI includes a capacity of 32 rope nodes. These implementation bounds matter when presenting authoring controls.
- Timing/events: fixed tick 1–1000 Hz, 1–240 catch-up steps, time scale 0–100, pause/single-step, interpolation and three dropped-time policies; body lifecycle, collision/trigger phases, sleep/wake and joint-break forwarding. Rust scene/component descriptors are smaller compatibility/support APIs, not proof that all frontend components are natively implemented.
- Rhai: compile/validation, atomic replacement of cached valid ASTs, lifecycle/time/contact/signal/task parameters, scalar/vector/array/map exports and metadata; read-only context snapshots; deterministic seeded random, input actions/devices via host snapshots, self/target entity commands, UI/animation/audio/navigation/game flow, timers/tasks/signals, saves, bounded RPC commands, graph traces, and permission-gated editor automation. Runtime defaults bound operations (100,000), call depth (32), arrays (8,192), maps (4,096), strings (262,144), host commands (4,096) and logs (512). Dynamic source evaluation and host imports are disabled. The returned commands still require TypeScript validation, identity checks and application.
- Format: legacy input projection and schemas through 29; scene/entity/component/asset identity; hierarchy cycle and reference checks; asset/pipeline metadata; plugin/package declarations; input, physics, animation/audio, build/delivery, world and networking settings. The Rust validator and TypeScript authoring validator have overlapping responsibilities; tests of one do not prove their full parity.
- Native host: deterministic/incremental export files, SHA-256 package/build integrity, embedded or sidecar package startup, output cache/patch/provenance/SBOM/deployment metadata, matching-host desktop export, gated Android discovery/manifest/build/deploy/log collection, project staging/backup/journal transactions, crash logs, external diff/merge, Git initialization, bounded native UDP sockets/peer scopes, and 2–8 managed network player processes. Signing/deployment metadata is not execution of public deployment or signing.

Every frontend edit that changes a body or child descriptor must invalidate/update its Rust record; every visual/code export must pass through the same Rhai compile/runtime path; every new command must have host application/validation; every event field must have a tested JSON name. Build readiness and inventory entries are declarations until these paths are exercised. The defects found here demonstrate why an API name, a fixture file, or a successful compile alone does not establish binding correctness.

## Checks executed

1. Baseline `cargo test --workspace --locked --offline`: 149 tests passed.
2. Baseline `cargo test --manifest-path src-tauri/Cargo.toml --locked --offline --lib`: 14 tests passed.
3. Added Rhai and event-JSON regressions, observed the expected failures, applied fixes, then all 23 Rhai tests and the new bridge test passed.
4. Added compound query regression, observed the expected failure, applied the query fix, then all 7 query tests passed.
5. `cargo test --workspace --all-targets --locked --offline`: 153 tests passed after those fixes; all examples compiled. The subsequent isolated schema fix passed all 41 format tests. The final integrated run then passed all **154 core tests in one run** (41 format, 2 math, 81 physics, 6 runtime, 23 script, 1 WASM bridge).
6. Expanded native path regression and full native lib suite: 14 tests passed.
7. Final workspace and separate native `cargo clippy --all-targets --locked --offline -- -D warnings`: passed; `cargo fmt --all -- --check`: passed.
8. Direct `wasm-pack build crates/nova_wasm --target web --out-dir ../../nova_core/pkg --out-name nova_core --release --locked --offline`: succeeded for runtime fixes, and succeeded again after the schema fix (final build 42.64 seconds).
9. Separate `node node_modules/typescript/bin/tsc --project tsconfig.node.json --noEmit`: initially reproduced the missing library/declaration/type errors; passed after the coordinated config and dependency fixes.

Native file/socket tests use bounded temporary fixtures. No release publishing, signing, public network messages, long-duration soak, non-Windows host build, hardware input test or independent-user qualification was performed by this backend audit. Browser/editor checks are owned by the main UI/runtime audit and must not be inferred from the Rust results.

The late project-lease follow-up additionally reviewed `src/runtime/teamWorkflow.ts` ownership operations, `src/projects/projectManager.ts` open/create/switch paths, `src/projects/projectSession.ts` metadata initialization and `src/runtime/recovery.ts` unload handling. `node scripts/verify-v26.11-project-locks.mjs` passes 13 behavioral checks for ordinary reload/reopen, independent editor exclusion, BFCache lifecycle, unrelated release, replacement ownership, expiry, project switching and unreadable storage. Ownership credentials were not copied into sessionStorage, because browsers can clone it into another tab. The change does not steal pre-fix orphan leases or guarantee cleanup after crashes/process termination, when `pagehide` may not run. Long-lived lease renewal, atomic acquisition across concurrent tabs and writer fencing after expiry remain separate qualification targets.
