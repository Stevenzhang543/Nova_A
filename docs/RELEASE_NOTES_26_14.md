# Nova_A 26.14 — object families and reliable runtime ownership

Engine 26.14.0. Project Format 2/schema 29, Rhai API 2 and Graph Format 1 remain compatible. The executed-gate manifest in this release's evidence archive identifies the qualified source, binaries and observed checks. Development results below are rerun against the integrated release; their earlier reports remain historical evidence.

Object Blueprints now validate inheritance, composition and placement before creating anything. Create a family, derive a child, instantiate it and override one instance through explicit history transactions. Static instances retain blueprint identity without requiring a Script component. Inherited Event Sheets resolve their actual callback authors and independent properties. Matching signal, connection and UI paths deduplicate by author and callback; custom task/destroy handlers use the correct argument family while existing zero-argument callbacks remain supported.

The Ownership view shows the source chain, property provenance, authored baseline, current runtime values, inherited events, composition and declared subscriptions. Navigate to the actual blueprint, Event Sheet or callback declaration. Runtime observations are detached and read-only. Invalid blueprint drafts and saved-base conflicts remain exact and recoverable; source navigation works against the actual open source draft. English, German and Chinese labels wrap with their controls, and narrow ownership comparisons stack. The Inspector header is capped so long names and200% text do not consume the entire content scrollport.

Runtime changes follow the shared code/graph/Event Sheet command path. Entity and pending handles carry lifetime generations, pooled reuse invalidates prior leases, and deferred structural queues preserve nested work for the next boundary. Destruction cleanup cancels timers, tasks and targeted pending work before reset/removal. Pools compare actual raw entity identity across Vue proxies, prewarm synchronously before start callbacks, and enforce configured capacity without an unrestricted allocation fallback. Ordinary prefabs without a configured pool retain ordinary spawning.

Hot reload validates the complete dependent program set in a candidate VM, transfers primary and inherited properties, and commits once. A compile or transfer failure leaves the live VM and caches intact. Reload applies while paused, uses exact source/graph/module snapshots and discards commands from replaced programs. Rollback history is consumed only after a successful apply. Runtime scene replacement preserves the actual persistent objects, IDs, descendants and handles; a failed installation restores the previous scene/world references. Outgoing destruction occurs after commit and before incoming awake/start.

The test runner uses actual compiler-discovered functions. It executes suite/case setup and teardown with isolated case state, retains cleanup failures and frees the VM even after compilation failure. The native CLI reports observed callback-entry coverage, not inferred helper/branch coverage. Dynamic arrays/maps, function values, closures and typed graph operations retain the26.12 language contract and real VM regressions. Debugging continues to pause at supported callback/command boundaries; arbitrary VM suspension is not provided. Timers/tasks are bounded to10,000 registrations,4,096 callbacks per frame and64 per timer; cancellation invalidates already prepared dispatch.

Actual Save/Open auditing also repaired pure prefab comparisons, supported raw/percent/base64 prefab JSON decoding, removed-component tombstone handling, and the native/WASM format registry for twelve already-existing gameplay components. These repairs preserve established document formats and reject malformed or unknown data rather than silently dropping it.

The localized manuals add a complete Enemy Family lesson. Its deterministic project contains base/derived behaviors, collision and UI events, an authored speed override, bounded pooling and paused reload exercises with expected results. Separate code, blocks and mixed Coin Trail projects plus a renderer-disabled authority provide cumulative language/workspace references. All five directories have their own project, controls and expected-output documentation; earlier releases' references are retained.

Common gates build the exact Windows/WASM/editor/player source, execute Rust tests and warnings-as-errors lint, check history/templates/layout, export and launch the enemy-family Windows game, and exercise the loopback authority. The authority is a renderer-disabled WebView. Exact-source local gate completion is required before publishing the eleven release artifacts; a calendar version alone is not qualification.
