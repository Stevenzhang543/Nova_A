# Nova_A 26.12 scripting UI

Scope: source ↔ graph structure coverage, range and node navigation, conversion review, and typed syntax field editing. The broader studio layout milestone remains 26.13.

## Consequences assessed before edits

- The existing mode switch already saves dirty source or graph before unmounting. The new guard retains that behavior for every destination, including Event Sheets, and prevents simultaneous switch requests. Invalid or unpreservable conversion stays in the current editor; source-backed conversion requires an explicit review of preserved source. Review acceptance is bound to the exact asset and source, so stale acceptance cannot approve changed code.
- Source parser offsets are UTF-16 and half-open. Browser textareas normalize Windows CRLF to LF. Direct offset selection would highlight the wrong characters, so normalization occurs only at the selection boundary; inspecting diagnostics does not rewrite source.
- The shared graph uses a shallow Vue ref. Centering a diagnostic previously mutated its viewport without invalidating the computed transform. Navigation now explicitly invalidates the graph ref. This changes the viewport and selection, without recording a content edit.
- New syntax field widgets use the graph schema's public setter, including the graph for binding-aware renames. They use the existing dirty, compile and undo path. Existing legacy graph creation remains available; the new action creates the separate typed Rhai structure.
- Graph coverage reads the last compilation snapshot, so panning or dragging the shallow graph ref does not reparse source on every animation frame. Field text limits match the schema's 8,192-character limit; setter failures remain visible in the inspector.
- Typed graphs do not use the old graph-level variable/routine/custom-event tables. Their inspector replaces those controls with the actual syntax declaration/function/module index, and initially opens the matching syntax palette family. Legacy assets retain the old tables. Code navigation flushes a pending compilation and remaps by node identity before selecting source, so edits that lengthen a literal do not use stale offsets.
- Ordered child controls add, remove and reorder real graph pins/slots. Stable keys and pin UUIDs keep existing wires attached during reorder. Removing a slot removes its incident wires, while its former child node stays available as a disconnected node. Structural edits set `structureChanged`, so the typed compiler regenerates the owner in the new order and retains its owned comments. This can normalize the owner's formatting. There is an explicit 128-pin limit with no silent truncation.
- Optional child toggles represent actual presence/absence for receiver, initializer, return/break value, else branch, loop counter, catch parameter, switch guard and module alias. Their declared default child is visible when unconnected; connecting a typed node replaces it. The existing generated-node fallback values are not arbitrary editable source fields.
- Syntax output pins use `result`, preventing collisions with scalar input fields named `value`. No previously qualified typed release existed, so this does not migrate legacy graph ports.
- A failed linked conversion previously restored script text but left its recovery source, saved hash and breakpoint metadata mutated. The source editor now restores that metadata as well, keeping the failed draft recoverable.
- Graph Save now passes the serialized visual asset draft to `GameplayRuntime.validateModuleSource` before any asset write. The shared module resolver compiles the visual document, resolves its host `use` dependencies, then invokes the actual script runtime. Validation failure or a runtime still loading leaves the graph dirty and shows a retryable error above the editor. No linked text asset is created just to perform validation.
- Actual browser checking found the source footer could say “Script is valid” beside parser errors. Its status now includes live analysis errors. Save failures now show the actual validation error directly in Problems, instead of requiring an offscreen Console search.
- Actual browser checking also found valid `use` dependencies produced false unknown-function errors in the code editor. Analysis now reads the exact draft/module bundle through a new read-only runtime accessor and supplies its parsed top-level function declarations to both worker and fallback analysis. Only those names are recognized and offered in completion; other unknown calls still report errors. Missing/cyclic dependencies stay visible, with current-file import errors selecting the exact source line. Dependency generation changes refresh analysis without replacing a dirty draft. This accessor copies override maps and performs no VM execution or debugger registration.
- The graph palette now uses graph-specific search text in all three UI languages; the shared translation previously mislabeled it as material-node search.
- Final review found the source editor's Rename action bypassed its language helper and replaced matching text across every project script. The action now captures the selected lexical binding and exact draft/asset, calls the parser-backed rename helper, refuses unresolved cross-script function references, validates before confirmation, checks the draft again afterward and saves through the existing linked-graph synchronization/rollback path. Comments, strings and shadowed bindings are not project-wide replacement targets. The confirmation now describes this actual scope in all three languages. Formatting helper refusals leave the draft unchanged; thrown failures are visible in Problems. Obsolete project-wide name lookup was removed.
- Graph name edits now provide other saved script sources to the same binding guard, excluding this graph's linked source. Shared consumers and ambiguous references can therefore stop an unsafe rename before node fields or history change; the existing inspector error displays the reason.
- The typed node input rows previously displayed legacy `pin.defaultValue` editors even though the typed compiler reads structural slot fallbacks. Those inactive controls are removed only from typed nodes. The rows now display the actual fallback, such as `0.0`, with localized guidance to connect a value node; typed Literal fields remain editable through the inspector. Legacy node input editors retain their behavior.
- Coverage counts syntax regions, including nested regions; they are not a percentage of runtime features. Source-backed code is explicitly distinct from editable structure. Compiler/runtime validation remains necessary after syntax analysis.
