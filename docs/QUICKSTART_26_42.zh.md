# Nova_A 26.42 快速入门：30 分钟做出第一个游戏

本文从 **Platformer Scene** 模板出发：修改角色移动参数、运行、导出网页版。最后用四条短说明讲清新手最容易困惑的时序规则。全程离线可用。

[English](./QUICKSTART_26_42.en.md) · [完整手册](../manual/index.html) · [脚本契约](./SCRIPTING_CONTRACT_26_23.md)

## 1. 打开模板（5 分钟）

1. 启动 Nova_A，在启动器中点 **New Project（新建项目）**。
2. 选择 **Platformer Scene**，填写项目名称和文件夹，点 **Create Project（创建项目）**。
3. 首次会弹出引导，可以看完，也可以点 **Skip for now（暂时跳过）**。

编辑器分三栏：左边是 **场景 / 层级**，中间是场景（工具条浮在场景上方），右边是 **检查器**。在层级中选中 **Player**，检查器先显示 Transform，再显示各个组件。

26.42 起，用模板新建的项目物理频率为 **120 Hz、4 个子步**（见说明 B）。旧版本创建的项目保持原来保存的频率。

## 2. 用 `@export` 修改移动参数（10 分钟）

1. 选中 **Player**，在检查器中找到 **Script（脚本）** 分组。脚本里标了 `@export` 的变量会显示为字段：`speed`（8）、`jump_speed`（12）、`gravity`（−22）。
2. 把 `speed` 改为 **11**，`jump_speed` 改为 **14**。修改随场景保存，不会改动脚本文件。
3. 想看这些值从哪里来，可切换到 **Script** 工作区，打开角色的 `.rhai` 文件。每个字段对应一行，例如：

   ```rhai
   @export(type="float", min=0, max=30, step=0.1, group="Movement", tooltip="Horizontal speed in world units per second") let speed = 8.0;
   ```

   `min`、`max`、`step` 限制检查器中可输入的范围；`group` 和 `tooltip` 只影响显示方式。

## 3. 运行与停止（5 分钟）

1. 点右上角的 **Play（三角形按钮）**。
2. 先点一下场景，让它获得键盘焦点，再用 **A/D** 或方向键移动，**空格**跳跃。
3. 运行时，指针停止移动 1.5 秒后浮在场景上的工具条会淡出；检查器大约每秒刷新 10 次，显示运行中的值。
4. 点 **Stop（停止）**。运行期间的所有改动都会恢复为编辑时的场景。想保留的修改请在停止状态下进行。

## 4. 导出网页版（10 分钟）

1. 打开 **Manage（管理）** 工作区，选择 **Build Settings（构建设置）**。
2. 选择 **Web** 目标和输出文件夹。导出结果包括 `index.html`、Nova Player 文件和 `game.nova-pak`。
3. 执行导出。用任意静态网页服务器提供该文件夹（多数浏览器禁止直接从磁盘打开 `index.html`），再用浏览器访问。导出的游戏不包含任何编辑器工具。

如果某个资源校验失败，导出会停止并给出资源名称。修复或删除该资源后重新导出。

## 四条时序规则

### A. `fixed_update` 负责移动，`update` 负责逐帧表现

- `fixed_update(dt)` 每个物理步执行一次，`dt` 恒定（新模板为 1/120 秒）。移动、施力，以及需要在不同机器上表现一致的逻辑放在这里。
- `update(dt)` 每个显示帧执行一次，`dt` 为帧时长。用于表现：文字、特效、镜头修饰。
- `input_pressed` 在 `update` 中只在按下的那一帧为真；在 `fixed_update` 中，按下后的第一个物理步为真。按键会一直保留到有物理步执行为止，所以不会因为某一帧没有物理步而丢失。持续按住请用 `input_down`。

### B. 物理频率决定一部分输入延迟

输入在下一个物理步生效，平均要等半个步长：60 Hz 约 8 ms，120 Hz 约 4 ms，240 Hz 约 2 ms。频率越高，每秒物理计算越多。模板采用 120 Hz、4 个子步，每秒子步总数与旧的 60 Hz × 8 相同。可在 **物理 → 物理更新频率** 中修改。

### C. 写操作在回调结束后才生效

改变世界状态的调用，如 `set_position`、`set_velocity`、`entity_set_position`、`apply_impulse` 等，会先排队，等回调返回后由引擎统一执行。同一回调内再读取，得到的仍是回调开始前的状态：

```rhai
fn fixed_update(dt) {
  set_position(9.0, 9.0);
  let x = transform().position_x;   // 仍是旧的 x
}
```

脚本变量（包括 `@export` 变量）则立即改变。如果同一回调里还要用刚写入的值，请先存到变量里。`scripts/verify-2642-script-write-read.mjs` 用随包发布的脚本运行时验证了这一行为。

### D. 碰撞回调和计时器何时触发

- 一帧内执行多个物理步时，这些步的碰撞和触发回调会在最后一步结束后一起派发，因此回调可能比接触发生的那一步晚一步或几步。需要逐步精确时，请在 `fixed_update` 中查询接触或位置。
- `timer_start(name, seconds, repeat)` 到期时调用 `on_timer(name)`。用 26.42 模板创建的项目使用**固定步计时器时钟**：计时器随每个物理步推进，在该步的 `fixed_update` 之前触发，因此在任何帧率下都在同一物理步到期。旧项目保持帧时间时钟，0.1 秒的计时器可能在两个物理步之间到期；可在 **物理 → 计时器时钟** 中切换。
