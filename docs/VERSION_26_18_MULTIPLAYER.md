Potential defects to reproduce before fixes:

1. sendNetworkPacket allocates reliable sequence numbers before payload/byte/window admission finishes. A rejected send can leave the receiver waiting forever for an unsent number. Planned owning files: networking.ts and a dedicated 26.18 regression. Consequence: only accepted outgoing packets should advance ordering; accepted retries keep identity.
2. receive commits replay state before channel rate admission. A temporary rate rejection can cause the eventual reliable retry to be treated as a replay. Planned owning files: networking.ts, networkProduction.ts if transactional replay admission is needed, and the regression. Consequence: reject true replays but permit packets previously refused before processing/buffering.
3. processPacket resync imports entity state before validating authority and acknowledges chunks before complete document acceptance. Planned owning files: networking.ts, networkProduction.ts/networkReplay.ts as necessary and the regression. Consequence: malformed baselines must preserve all prior state and expose failure; valid baseline behavior remains compatible.
4. Connection callbacks and service awaits are not uniformly guarded by connectionGeneration. Review cancel/reconnect races before editing. Consequence of any fix: a stopped/replaced session must never be revived or receive old callbacks.

Initial documentation additions: this journal, the acceptance tracker and EDIT_LEDGER_26_18.md. They add development records only, remove no behavior and make no audit-pass claim.
