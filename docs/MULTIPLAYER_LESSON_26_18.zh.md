# 26.18 多人协作练习

分别复制 `multiplayer-v2618-coop-host` 和 `multiplayer-v2618-coop-client`。两份项目共享场景、实体和脚本标识，提供两个玩家位置；增加客户端不会自动增加角色。网络是可选功能，示例初始不授予权限，也不自动连接。离线项目不需要网络服务。

## 连接并观察

在同一浏览器来源下的两个独立编辑器窗口打开主机和客户端。保持两个窗口持续渲染；浏览器可能暂停后台标签页的动画更新。进入 Network Studio → Session，分别明确授予网络权限，保持 Local lobby 和相同会话名称，先连接主机，再连接客户端。双方节点列表应显示对方不同的玩家标识。本地频道要求同一设备、来源和浏览器存储分区；不同浏览器配置或来源不能因此组成互联网会话。

两边点击 Play。聚焦主机画布，用 WASD 或方向键移动 Host Player。聚焦客户端画布，客户端通过有界 `coop.move` RPC 请求主机移动 Client Player，再把结果同步到双方。Stop 恢复编辑状态。若不能移动，依次检查运行状态、画布焦点、权限、连接、节点接纳、RPC 合约和脚本错误。传输层已连接不代表游戏已经运行。

## 所有权与属性

Server 权限表示由主机或服务器计算复制状态。Owner 表示由指定节点持有；空的所有者不会允许任意客户端接管。试验时选择对象，在 Replication 添加复制描述，选择 Owner 并输入已接纳的节点 ID，或在 Orchestration → Authority transfer 明确转移现有所有权。先检查双方诊断，再操作对象。主机转发的快照不能覆盖本地所有者的新状态。随附协作游戏保持服务器权限，因为其脚本让主机执行远端角色移动。

Transform、Rotation、Velocity 可以分别选择。普通快照和中途加入都遵守属性选择。这里的 Transform 指位置；缩放、启用状态和角速度不是额外的实时复制字段。手动多人存档会保存并恢复更多状态，这是明确的存档操作。Interpolate 平滑允许复制的远端字段；Predict 重放已记录的变换增量，不重新执行物理或脚本。父对象世界变换先于子对象处理。

## 编辑与恢复

Protocol 卡片提供名称、有序可靠或顺序快照传输、载荷字节数、消息速率和优先级。RPC 卡片提供方向、权限、载荷类型、大小和调用速率。Object 类型不自动检查游戏自定义字段：脚本必须验证自己的载荷。RPC 只能使用约定的频道。运行时增删 RPC 合约会在生产更新中同步到游戏监听器。

数值离开输入框时提交。先输入超界值再修复：无效输入应保留原设置并显示错误，有效值应正常生效。验证撤销、重做、保存和重新打开。修改会话身份、传输、认证或频道身份会停止旧连接，需要点击 Reconnect；属性和所有权可以实时修改。重连恢复接纳和基线，不恢复任意应用历史。

断开客户端，移动主机，然后重新连接。观察当前状态和中途加入计数。基线在校验后原子应用；所有权、元数据、大小或校验和错误不得造成半恢复世界。可靠重试耗尽会移除该节点的队列并报告可操作的错误。已跟踪连接生命周期内的旧纪元不能继续游戏消息。校验和不能替代认证；安全敏感适配器必须明确配置经过审核的认证。

## 诊断、模拟与导出

Simulation 可设延迟、抖动、丢包、重复、乱序和随机种子。先验证无干扰连接，再适度增加干扰，比较节点身份、ACK、重试、拒绝数和历史上限。模拟重复时出现重复拒绝是预期现象，需与可靠消息停滞区分。快照分页计数表示最近一个目标节点；延后实体将在后续快照间隔发送，并非每帧原子同步整个大型世界。

实例 Logs 显示编辑器观察到的该进程事件；Inspector 显示进程身份和状态。游戏状态及网络事件应在实际运行的玩家窗口检查。这不是原生远程调试器，也没有收集完整子进程标准输出。导出诊断后，分享前检查敏感信息。

导出协作玩家前，明确授予权限并启用随游戏自动启动，检查角色和会话，再一起运行实际产物。本地玩家需要受支持的相同来源和存储环境。Windows 直接 UDP 中，客户端指向主机监听端口，各客户端使用不同本地绑定端口。单独的服务器参考导出为禁用渲染器的 Windows WebView 玩家，仍需要桌面宿主和 WebView；它不是无窗口 Rust 服务器。真正独立服务器的设计及验收条件见 NATIVE_SERVER_ARCHITECTURE_26_18.md。

## 回滚边界与验收

变换增量重放不会恢复求解器接触、Rhai 作用域、实体生命周期、音频、UI、文件写入、插件或外部服务。不要通过任意重跑游戏帧伪装完整回滚，否则可能重复外部副作用。公网匹配、转发和认证需要明确选择服务商并进行独立基础设施验证。

为自己的项目记录两个不同玩家移动、所有权修改、断开重连、中途加入、无效及有效编辑、撤销重做、保存重开、实际客户端与服务器导出结果及日志。比较代码、积木和混合参考：生成图应编译为相同源代码并产生相同游戏行为。生成参考文件或单元测试通过本身不能证明用户流程成功。
