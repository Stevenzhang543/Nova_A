# Nova_A 26.21–26.30 competitive review

Reviewed 2026-09-11. This comparison defines work, not parity certification. The [source inventory](SOURCE_MAP_26_21.md) and [operation/component/API/node inventory](FEATURE_INVENTORY_26_21.md) identify Nova_A ownership. Catalog counts cannot measure engine completeness.

| Projects/editor | Scenes, hierarchy, components, prefabs, workspaces, history, recovery, packages and semantic merge | Mature engines make property changes predictably undoable and inspectable. Nova_A needs field-level lifecycle evidence, not just shared route declarations. | 26.21–22 |

Defold's documented live reload illustrates why lifecycle contracts matter: initialization does not simply rerun and module references can need special handling. Nova_A should test retained state and invalidation explicitly. These are workflow comparisons, not claims that every competitor implements every listed behavior. A 3D/XR engine, proprietary-console support and a second general-purpose scripting runtime are outside this 2D roadmap unless separately authorized.

## Scripting details that affect the next implementation

Nova_A's runtime actually uses Rhai `Dynamic`, arrays/maps, compiled ASTs and scoped execution in `crates/nova_script/src/lib.rs`. It also configures operation, call-depth, expression-depth, string, array and map limits and a progress callback. Those are concrete sandbox/runtime controls; an editor annotation must not be advertised as VM-enforced static typing unless execution verifies it.

Project modules have a narrower contract than general Rhai modules: `src/runtime/scriptModules.ts` rejects native `import`/namespace syntax and accepts standalone, constant-path `use "path";` dependencies at module scope, without aliases. The current limits include 256 modules, depth 32 and a 1,000,000-character bundle. Therefore “modules supported” is not equivalent to unrestricted namespaced modules or dynamic module loading. 26.23 must decide and test namespace/isolation semantics before expanding this contract. Keep existing projects readable and diagnose unsupported syntax rather than silently flattening incompatible names.

`src/runtime/scriptHotReload.ts` already models compatible/recreate/restart/rejected plans, per-property transfer actions, history and rollback sources. The next release should deepen and test that implementation, not add a duplicate hot-reload toggle. Test actual VM compilation and dependency invalidation, state transfer, failed candidate rollback and source revision handling. Godot's await and class model and GameMaker's structs/method bindings are useful comparisons, but they do not imply that Nova_A should emulate incompatible language semantics through misleading editor-only metadata.
