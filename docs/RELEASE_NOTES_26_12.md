# Nova_A 26.12 — shared Rhai structure and reliable conversion

Engine 26.12.0. Project Format 2/schema 29, Rhai API 2 and Graph Format 1 remain in use. These notes describe the source change. The included executed-gate manifest determines qualification status and identifies the precise source and binary hashes.

New Rhai companion graphs represent declarations, lexical bindings, arrays/maps, access and assignment, operators, function calls/returns, typed receiver methods, closures, branches, supported loops, exceptions, interpolation and exports as editable connected syntax. Source spans preserve unchanged comments and spelling. Structural edits regenerate the edited owner; continued strings and escaped map keys retain their values. Invalid or over-limit source produces a specific diagnostic rather than a truncated graph.

Code and Visual share conversion review, current-source diagnostic navigation and failed-save guards. Typed graphs have ordered-child controls, optional-child controls, field editing, declaration navigation and actual VM validation before saving. Editor and language-server diagnostics, completion and formatting use the same syntax model. Parsed declaration renames follow their lexical binding and reject capture, duplicate declarations and unsafe external references before changing the draft. Formatting preserves multiline strings and comments. The overload palette is generated from the actual Rust/Rhai registration inventory; float and integer parameters are distinct, insertion literals are not optional arguments, and values without a safe placeholder require a connection. Runtime tests are still needed for dynamic overloads and game behavior.

Existing execution graphs keep their compiler and visible source-backed blocks. They are not silently advertised as fully structural. New typed metadata is additive; retain a backup before using an older editor that does not understand that representation.

Text and visual assets resolve project-local `use` dependencies through the same token-aware, bounded resolver. Dependencies initialize once in dependency order. Comment/string lookalikes, missing modules, cycles and invalid aliases cannot silently change the bundle. Inspector exports use that same source bundle. Rejected compilation does not replace active debug/cache state. Blocking `sleep`, including indirect function-pointer dispatch, is rejected with timer/task guidance because it blocks native execution and panics in WASM.

The three Coin Trail references use the same playable route and source with different Script2D bindings. All fifty shipped Rhai starter scripts participate in exact conversion checks. English, German and Chinese manuals include a concrete code/visual exercise, failure repair and reference-game controls.

The release tooling accepts the requested sequential versions 26.13–26.16. It freezes actual authored dirty/untracked sources, records real commands and reports, verifies embedded native versions and full web payload hashes, and refuses to overwrite a finalized version. Each release has eleven artifacts under its own `releases/v26.12` directory; the existing contract is recorded in VERSION_26_12_RELEASE_PLAN.md.

## Audits and limits

Language and graph suites compare independently regenerated programs in the real VM, including commands, logs, properties and error behavior. Additional cases exercise malformed/truncated input, generated programs, recursion, shadowing, closure capture, numeric spellings, source identity, ordered ports, optional children, required inputs, cycles and serialization. Browser authoring exercises actual controls and save/cancel behavior. Common build, history, template, layout, Windows, authority, benchmark and stability gates retain their exact observed scope in the evidence archive.

The projection has explicit source/node/pin limits. Local function values execute but cannot become persistent serialized closure identities. Native import namespaces, `eval` and `await` are outside the declared sandbox. Dynamic runtime failures remain possible even when source parses. This milestone does not certify every possible game, independent usability, physical assistive technology, untested platforms, installer lifecycle on clean machines, signing, or a long-duration soak. Graph interaction and complete workspace layout continue in 26.13; later versions are specified separately in ROADMAP_26_11_TO_26_20.md.
