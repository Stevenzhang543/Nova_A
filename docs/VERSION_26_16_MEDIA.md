## Integration contracts

- `MediaClock.seek/advance/snapshot`, `mediaSample`, `mediaFrame`, `mediaFrameTime` are exported. The runtime media clock follows **actual evaluated fixed steps**, including scaled physics accumulation, rather than advancing by render time that may have been capped/dropped. Animation, timeline captions, audio transport, bus automation and runtime tile frames consume this evaluated clock. This does not change RuntimeTime timer/script semantics.
- `animationRuntime.applyTimelineSamples([{key, owner, clipAsset, time, weight, additive?, loop?}], entities)` returns keyed diagnostics. Normal overlap weights sum to one when their total exceeds one; totals below one retain the underlying pose. Sprite selection is discrete.
- `animationRootMotionDelta(clip, previous, next)` returns `{x,y,rotation}` across complete loops. `applyAnimationRootMotion(entity, delta, weight)` adds it explicitly. No existing Apply scene semantics are redefined.
- `timelineRuntime.seek(ownerUuid, entities, seconds)` preserves play/pause and suppresses events across the jump. `timelinePresentationState.diagnostics` retains failures. Nested audio inherits the original player's play state and all nesting rates, even if the target entity has no TimelinePlayer.
- `audioRuntime.setTransportTime({seconds, playing, scale})` and optional fourth `update` argument set the common clock. `reconcileTimelineVoices(requests, entities)` uses `{key, ownerUuid, entity, reference, time, playbackRate, gain, playing}`. `diagnostics.clock` and `voiceClocks` expose exact requested sample positions/rates and playback state. `dispose()` synchronously releases authored ownership before awaiting device-context close.
- `recordingStatus().limited` reports capacity. Between actual evaluated poses, extra recording frames use linear interpolation; this is resampling, not a claim that unobserved intermediate physics was simulated. A failed save retains the recording.

## Explicit limits and compatibility details

Decoded audio allows 64 MiB resident PCM (including reversed copies), 32 MiB compressed/decoded data per clip, and 16 simultaneous decodes. Large clips should use Stream. Buffered playback supports finite signed rates through magnitude 1024. The media-element streaming path supports the browser's rate range (checked as 0.0625–16 and also catches host refusal); unsupported signed/high streaming rates stay paused at the requested sample with diagnostics. Streaming seek resolution/output still depends on the decoder and browser; integer requested sample diagnostics do not assert physical hardware sample accuracy.

Animation curve cuts can require a representation that the old easing enum cannot express exactly. Adaptive piecewise-linear baking checks quarter/mid/three-quarter error against the runtime evaluator at absolute tolerance 1e-6 and refuses after 10,000 keys or depth 24. Dense independent sampling fixtures cover Linear/Cubic/Step cuts. This is an explicit bounded approximation, not a claim of symbolic identity for arbitrary curves. Preview refuses more than 100,000 samples; animation reimport refuses more than 10,000 keys per track or 250,000 total resamples. Recording stores at most 10,000 samples per numeric track, including frame zero, matching the serialized animation limit.

Timeline documents allow at most 100,000 clips; a traversal allows eight nested levels, 100,000 visited clip instances, 10,000 collected commands and 64 marker jumps. Rig normalization rejects more than 2,000,000 estimated pose operations. These errors are explicit rather than partial silent computation. Animation/controller/mask cache bounds are 512 entries each; rig/skin are 128 each; timelines are 256, with generation invalidation.

Existing audio loudness/true-peak fields are RMS/sample-peak estimates, not a BS.1770 analyzer or oversampled true-peak measurement. The UI owner was notified to label those estimates. Physical devices, output latency, underruns under real load, streaming network/device recovery and human hearing/accessibility require the matching-host user audits; the automated evidence below does not replace them.

## Animation UI transport additions

UI-owner method-only additions to src/runtime/animation.ts expose detached inspectClipPlayback, seekClipPlayback through the existing sampleClip/applySample evaluator, and per-entity stopClipPlayback. Seeking never advances other clocks or dispatches traversed events; simulation Play/Pause and authored restoration remain owned by the caller's real runtime session. Missing target/asset refuses without changing current transport; nonfinite time raises an actionable error.

scripts/verify-v26.16-animation-audio.mjs adds three actual-evaluator groups for detached inspection, crossed-event suppression versus subsequent playback, repeated backwards sampling, atomic invalid requests and independent transport stopping.
