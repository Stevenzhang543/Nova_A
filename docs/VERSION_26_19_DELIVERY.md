# Nova_A 26.19 delivery implementation journal

## Reviewed before edits

The 26.11–26.20 roadmap owns scope. Preserve all public schema/API versions. Baseline matches the complete 26.18 snapshot. No dependency pin changes are justified yet.

Semantic collaboration: existing array merge uses base order even when a side intentionally reorders; conflict assignment cannot restore an absent array identity; JSON-pointer escaping handles slash but not tilde. Consequences of repair: preserve explicit ordering and stable identities, require an explicit choice for incompatible orders, allow repeatable choices without deleting independent edits. Duplicate identities must be rejected rather than collapsed by Map. Regression tests precede changes.

Package lifecycle: permission approval mutates installed grants before an update that may fail; rollback removes history before validation and mutates the package before dependency resolution. Consequences: stage candidates, validate the complete dependency graph and only commit on success; rejected actions preserve grants, history, installed state and lockfile.

External changes: asynchronous reads use shared watcher state after await, allowing a stopped/old watcher to affect a new project. Consequences: bind each read and timer to a generation; stale completions cannot signal changes or install timers. Invalid external files retain a visible error and can be retried.

Signed updates: signature verification yields while opt-in/channel/applied state can change. Audit cancellation, concurrent staging, minimum version and commit origin. No implicit download or installation is authorized by staging; installer qualification remains separate.

Audit routes: focused executable regressions; actual visible editor flows including undo/save/reopen/export; locale/theme/scale/width coverage for every changed panel; clean-source and moved-checkout build; final source-bound release qualification. Record actual failures and unresolved platform prerequisites rather than relabeling old evidence.
