# 26.15 asset pipeline reliability — isolated implementation

Integration notice: this journal retains historical staged paths, intermediate failures and pending-at-the-time entries. Its reviewed authored files are integrated for26.15 after26.14 was separately finalized. Current behavior and final evidence boundaries are in [26.15 release notes](RELEASE_NOTES_26_15.md); source-bound executed gates determine production/native qualification. Copied build/check roots and generated reports are not promoted as source authorities.

This document records the asset-core portion of roadmap 26.15. It is staged in `.cache/development-v26.15`; active 26.12 source, release packages, and the separate 26.13/26.14 overlays were not changed by this work. Renderer output, asset-panel interactions, library discovery, actual native/browser export playback, and manual sprite-sheet child generation are separate integration responsibilities. This is not evidence that the whole 26.15 release is complete.

## Consequences assessed before implementation

The existing reimport path wrote replacement bytes before late image/audio metadata work, so a late failure could destroy the previous valid artifact while reporting failure. Retry records did not retain the destination UUID. Reference repair replaced substrings inside source, including unrelated prefixes and prose. Build closure discarded missing/excluded nodes, inferred scene roots from embedded asset inventory, and the package writer applied a second optional-asset filter after caller selection. A fixed cache-entry count could still retain excessive bytes. Atlas groups could share the same page, and asynchronous image failure could produce partial output.

The changes below make failed preparation retain authored state, make selection failures block export before output, and introduce explicit resource budgets. Existing serialized UUIDs and source-key frame identities are retained. A pipeline-version/cache namespace change invalidates disposable importer caches; authored assets are not evicted. Ordinal artifact ordering can change hashes for non-ASCII keys/groups/paths compared with a locale-dependent old build. Existing caller APIs remain available; additive APIs are listed below.

## Shared contracts

- `selectBuildAssets(assets, groups, project, {include, exclude, stripUnusedAssets})` returns `{assets, closure, diagnostics}`. Each closure entry has `uuid`, `path`, `groupId`, `mode`, `owner`, `reason`; `issue` may be `missing`, `editor-only`, `unknown-group`, or `invalid-source`, with `sourceError` where applicable. Required assets excluded by a build rule are errors. Explicit inclusion is not silently expanded to override exclusion. With stripping disabled, allowed non-editor assets are roots; with stripping enabled, only scene/project roots and their dependencies are selected.
- `readResourceFromAssets(reference, assets)`, `resolveResourceFromAssets(reference, assets, variant?)`, and `resourceVariantNames(document, assets?)` support captured project contexts. Existing global-state wrappers remain. A null resolve is failure, not a usable default result. Saves return false without mutation for invalid inheritance/selection.
- `resolveInterchangeTexture(asset, assets)` returns `{reference, diagnostics}`; `bindInterchangeTexture(asset, assets, previous?)` is the explicit mutator used after batch import or on a detached reimport candidate. Consumers must use `textureAsset` and the imported slice metadata; a filename is not a stable identity.
- `processAssetImport(file, settings, {targetUuid?})` retains destination identity for retry. `assetImportRetentionStats()` reports live retention; `clearAssetImportSession()` aborts jobs, stops watchers and drops disposable cache/retry/change ownership when changing project.
- `createNovaPak(..., {authoritativeAssets:true})` trusts an already validated selected list. It does not itself reconstruct scene/module dependencies. The common exporter supplies that option only after selection passes.

## Limits and intentional behavior changes

Source reads are capped at 512 MiB. Disposable importer memory cache is 64 MiB/128 entries; persistent cache 256 MiB/128 entries; retry retention 64 MiB/32 files; jobs 128; watched files 128; pending external changes 64. Oversized retention entries are not cached. Image metadata rejects more than 32,768 pixels on an axis or 268,435,456 total pixels. Image/audio/font metadata preparation has a 15-second timeout.

Atlas processing allows 16,384 sources, four simultaneous decodes, 134,217,728 aggregate decoded pixels and the same aggregate page-pixel limit, with pages from 64 to 8,192 pixels and a 15-second decode timeout. Failure leaves the prior installed atlas active. These are finite CPU-side preparation limits; they are not proof that every device can allocate the maximum. The runtime atlas still scales oversized images as before and does not implement rotation from the separate deterministic packing report.

Dependency text is limited to 16 MiB, one million traversed values and 64 nesting levels; Rhai dependency scanning additionally follows the shared lexer limits (one million UTF-16 source units). Cycles retain at most 256 diagnostic paths. Imported interchange text/generated text is capped at 16 MiB; the result cache is 32 entries/64 MiB; Tiled generated layers have an aggregate 4,194,304-cell bound. Existing interchange caps remain 65,536 frames, 128 layers and 256 tilesets. Resource chains have 64 levels and each resource has at most 128 local named variants. Existing resource normalization caps still apply to nested JSON, arrays, fields and strings; these were not redesigned into a lossless arbitrary-data format.

This is **not** a browser click audit, real decoder/renderer pixel comparison, native executable export, or maximum-budget allocation benchmark.

## Remaining integration and coverage boundaries

1. Root-owned 26.15 UI/rendering work must consume stable texture bindings, imported pivots/rotation/trim/duration/colliders, visible dependency/error recovery and resource variants, then verify actual rendered browser/native output. Manual `sliceSpriteSheet` still creates fresh child UUIDs and copied source snapshots on repeated slicing; that requires a parent/source-key child contract and reimport propagation.
2. Tiled import remains a bounded subset: JSON finite array layers and basic tilesets; the existing XML reader handles CSV layers but does not preserve full Tiled semantics. External/multiple tileset linkage, infinite chunks, encoded/compressed layers, flip/rotation GID flags, object/collision geometry, unequal animation durations and actual contextual-map consumption need dedicated implementation and fixtures. No complete Tiled fidelity is claimed.
3. Static dependency collection can resolve literal UUIDs/paths and supported `use` modules; runtime-computed strings cannot be inferred. Such projects should keep required dynamic assets through inclusion policy/non-stripped builds until explicit dynamic dependency declarations exist. Existing global production validation may reject invalid unused resources before the narrower closure gate.
4. Compression/texture-format settings are not new BC7/ASTC/audio transcoding implementations. Atlas packing metadata is not renderer correctness evidence. Device limits, context loss, shader fallback and final lighting/material/camera/particle outputs remain root-owned qualification.
5. Browser persistent cache behavior is tested with faithful API-shaped fakes, not actual quota eviction on every browser. Font validation executes when FontFace is available; an environment without that API cannot provide decoder evidence. Original source files are never deleted or rewritten by cache cleanup.
